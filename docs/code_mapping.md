# Code Mapping: Paper, R Reference, Python Implementation

Source basis:

- `docs/paper_notes.md`
- `docs/model_equations.md`
- `docs/r_reference_analysis.md`
- `docs/python_implementation_overview.md`
- Inspected source files in `src/`

Scope: This table maps paper concepts and algorithmic steps to the R reference implementation and the current Python implementation. It is an audit map, not a fix plan. Differences are classified conservatively: Python is not assumed wrong merely because it differs from R.

| Paper concept / equation / algorithm step | Paper reference | R implementation reference | Python implementation reference | Status | Notes |
|---|---|---|---|---|---|
| Core structural equation `Y = alpha + beta_1 P + xi` | Equation (1), p. 7; Equation (4), p. 10; `docs/model_equations.md` Section 1 | Simulated examples and final regressions in `ICAReg.R`; control-function final regressions lines 335-358 and 505-523 | `DataGenerator.generate()`, `src/data_generator.py` lines 115-121; final OLS in `src/icaEstimator.py` lines 149-165 | likely correct but needs verification | Python implements the minimal simulated DGP directly. | Endogenous-regressor equation `P = eta + rho xi` / `P = eta + rho v` | Equation (2), p. 7; Equation (3), p. 10; `docs/model_equations.md` Section 2 | R examples generate endogenous variables before calling `ica_reg()`; estimator assumes observed `P` variables | `DataGenerator.generate()`, `src/data_generator.py` lines 116-120 | likely correct but needs verification | Python implements the simple proof-style DGP `P = eta + rho * xi`. | Non-normal exogenous component `eta` | Equation (2), p. 7; Assumption 2, p. 11; Section 4.7, pp. 39-40 | R estimator assumes non-normality and selects most-normal ICA component; does not generate distributions inside `ica_reg()` | `DataGenerator._generate_eta()`, `src/data_generator.py` lines 49-113 | incomplete | Python supports many distributions, including `normal`. | ICA algorithm | Section 2.1, pp. 9-10; Listings 1-2 use `method = "jade"` | Default `method = "jade"`; `ICAReg.R` line 261; ICA calls pass method lines 322, 493 | `sklearn.decomposition.FastICA`; `src/icaEstimator.py` lines 10-11 and 124-132 | inconsistent with the R implementation | This is the known critical FastICA-versus-JADE audit point. | Selection of most-normal ICA component | Section 3.1, p. 16; Section 3.2, p. 18; paper does not specify statistic | KS test against normal with component empirical mean/sd; `ICAReg.R` lines 325-331 and 496-502 | Standardizes each component and applies KS test against standard normal; `src/icaEstimator.py` lines 134-147 | likely correct but needs verification | Standardizing then testing against standard normal is broadly equivalent to R's empirical mean/sd KS setup if component variance is nonzero. | Control-function final regression (`CF = TRUE`) | Section 3.1, p. 16; Section 3.2, pp. 18-19 | Adds `control_func` to final regression; `ICAReg.R` lines 335-358 and 505-523 | Adds `control_func` to final design if `self.CF`; `src/icaEstimator.py` lines 152-155 | likely correct but needs verification | This is closest to the paper's explicit method. | Intercept handling | Equations include `alpha`; paper examples use `lm`; formula-level `-1` not discussed | Detects intercept and removes it before ICA / final regression if requested; `ICAReg.R` lines 266-267, 315-318, 339-346, 380-386 | Parses `-1`; adds constant in rank check and final OLS; residualization usually forces intercept; `src/icaEstimator.py` lines 46-50, 81-87, 91-97, 161-164 | likely correct but needs verification | Python intentionally forces an intercept in residualization by default, similar to R `lm()` behavior. Exact `-1` behavior with exogenous residualization remains an audit point. |
| Formula syntax `Y ~ P | X` | Paper does not define software formula; R README defines syntax | `nlme::splitFormula(..., sep = "|")`; `ICAReg.R` line 264; README lines 2-8 | Manual string parsing; `src/icaEstimator.py` lines 46-62 | incomplete | Python supports simple `+`, `|`, and `-1`, but not full R formula features such as `as.factor()`, transformations, interactions, or robust parsing. | Input validation | Paper does not specify software validation | Checks missing, numeric, constant variables, rank; `ICAReg.R` lines 274-312 and 414-466 | Checks missing, numeric, constant variables, rank; `src/icaEstimator.py` lines 65-87 | likely correct but needs verification | Python validates all variables as numeric, including exogenous variables.
